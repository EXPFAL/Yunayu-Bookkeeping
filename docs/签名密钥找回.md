# Android 签名密钥找回（旧开发机操作手册）

> 目标：在**之前用来打包/安装到手机**的那台电脑上，找回与已装 APK **同一套签名**的密钥文件，以便新环境能覆盖更新，而不必卸载丢数据。  
> 包名：`com.expfal.yunayu.app`

## 0. 安全红线（必读）

1. **私钥不能明文提交进 Git 仓库**（不要 `git add *.jks` / `*.keystore`）。一旦进历史，视为泄漏。
2. 仓库只允许提交本说明文档；密钥请用下面「安全上传」方式之一。
3. 不要在本文件或 Issue/PR 里写 keystore 密码。

---

## 1. 在旧电脑上找密钥文件

本项目当前**没有**配置 release 签名，历史上手机安装包多半是 **Android Studio / Gradle 默认 debug 签名**。

### 1.1 优先找 debug.keystore

在旧电脑 PowerShell 中执行：

```powershell
$ks = Join-Path $env:USERPROFILE '.android\debug.keystore'
Test-Path $ks
Get-Item $ks | Format-List FullName, Length, LastWriteTime
```

常见路径：

- `C:\Users\<旧用户名>\.android\debug.keystore`
- 若换过 Windows 用户/重装系统，旧盘里可能是 `D:\...` 下对应用户目录的 `.android\debug.keystore`

### 1.2 再搜整个用户目录 / 工程副本

```powershell
Get-ChildItem -Path $env:USERPROFILE, 'D:\WORK', 'D:\LEARN' -Recurse -ErrorAction SilentlyContinue -Include *.jks,*.keystore |
  Select-Object FullName, Length, LastWriteTime
```

把搜到的路径记下来。

## 2. 打印指纹（用来和手机上的包对照）

### 2.1 密钥指纹

```powershell
# 默认 debug 口令一般为 android / 别名 androiddebugkey
keytool -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -storepass android -alias androiddebugkey
```

关注输出里的 **SHA-256**（以及 SHA-1）。

若文件不是默认 debug，尝试：

```powershell
keytool -list -v -keystore 'C:\完整路径\xxx.jks'
# 会提示输入 store 密码；别名用 keytool -list 先看有哪些 alias
```

### 2.2（可选）从手机已装 APK 读证书指纹

把手机上的安装包拷到电脑后：

```powershell
# 需本机 Android SDK build-tools 中的 apksigner，或用 jarsigner/keytool 对解压后的 META-INF
apksigner verify --print-certs '.\从手机导出的.apk'
```

**只有密钥的 SHA-256 与 APK 证书 SHA-256 一致，才是对的那把钥匙。**

## 3. 安全上传到 GitHub（推荐顺序）

### 方式 A：GitHub Actions Secret（推荐，不进仓库历史）

在**能登录本仓库的电脑**上（旧机也可，需已装 [GitHub CLI](https://cli.github.com/) 并 `gh auth login`）：

```powershell
# 将 keystore 转为 base64 一行（勿把输出贴到公开聊天）
$ks = "$env:USERPROFILE\.android\debug.keystore"
[Convert]::ToBase64String([IO.File]::ReadAllBytes($ks)) | Set-Clipboard
# 或写入临时文件再设 Secret：
[Convert]::ToBase64String([IO.File]::ReadAllBytes($ks)) | Out-File -Encoding ascii -FilePath "$env:TEMP\yunayu-ks.b64"

gh secret set YUNAYU_UPLOAD_KEYSTORE_B64 --repo EXPFAL/Yunayu-Bookkeeping < "$env:TEMP\yunayu-ks.b64"
Remove-Item "$env:TEMP\yunayu-ks.b64" -Force
```

同时把指纹记在私密处（或再建一个 Secret，例如 `YUNAYU_UPLOAD_KEYSTORE_SHA256`），方便新机器校验。

> 设好 Secret 后，在仓库 Issue 里留一句即可：  
> 「已上传 `YUNAYU_UPLOAD_KEYSTORE_B64`，SHA-256=……」  
> **不要**把 base64 正文贴进 Issue。

### 方式 B：加密压缩包（不进 git，用网盘/私聊传给新电脑）

```powershell
# 需要旧机记得密码；密码不要写进仓库
Compress-Archive -Path "$env:USERPROFILE\.android\debug.keystore" -DestinationPath "$env:USERPROFILE\Desktop\yunayu-signing-DO-NOT-COMMIT.zip"
```

再用 7-Zip / BitLocker / 带密码的加密工具保护。传到新电脑后放入例如：

`%USERPROFILE%\.android\debug.keystore`  
（先备份新电脑上现有的 debug.keystore，再覆盖。）

### 方式 C：禁止

- `git add debug.keystore` / 提交到 `cursor/*` 分支 / 开 PR 带密钥  
- 把 keystore 或 base64 贴到公开 README、PR 描述、截图

---

## 4. 新电脑拿到密钥后怎么用

1. **校验指纹**与手机 APK 一致。  
2. 将文件放到新机 `%USERPROFILE%\.android\debug.keystore`（或配置 `app/build.gradle.kts` 的 `signingConfigs` 指向该文件）。  
3. 再执行 `assembleDebug` / 安装，即可覆盖更新。

若只是临时：也可用 `apksigner` / `jarsigner` 用找回的密钥重签 APK（需与打包证书算法匹配）。

---

## 5. 给旧电脑的最短检查清单

- [ ] 找到 `\.android\debug.keystore` 或其它 `.jks`  
- [ ] `keytool -list -v` 得到 SHA-256  
- [ ] 与手机 APK 证书指纹比对一致  
- [ ] 用 **Secret / 加密包** 交给新电脑，**不** `git commit` 密钥  
- [ ] 在仓库开一条 Issue：`签名密钥已按 docs/签名密钥找回.md 上传 Secret（或已加密送达）`

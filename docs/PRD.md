# 云娅记账产品需求文档（PRD v2）

> v2 对齐 1.2.0 现状：初版 P0/P1 多数已交付，账户/转账/订阅/备份/报告重构超出初版范围；学生专属细节与隐私红线部分未做。以本文为准，历史过程见文末「交付演进」。

定位：**个人独占 · 学生向 Android 原生记账应用**
三大核心诉求：**学生财务自律 / 学业生活融合 / 极简高效记录**

产品人格（后续功能决策的锚）：
- **身份**：在校学生，生活费按月/按周周转，有学业开支与兼职，不做多账户理财
- **日常**：课间/排队 3 秒记一笔；每周日复盘提醒；生活费花到哪、还能花多少是第一问
- **口吻**：提醒不说教（「本周还剩 ¥320」而不是「你已超支！」）

---

## 一、功能矩阵（对齐 1.2.0）

### 核心：记账（已交付）

| 能力 | 现状 |
| --- | --- |
| 3 秒极速记账 | 首页 FAB + 自定义数字键盘；手动记/自动记双模式；收/支/转账 |
| 自然语言记账 | 在线 OpenAI 兼容 API；未命中标签直通未分类；备注必有 |
| 备注 | 手动记可选备注；NL 保证备注；按备注建议已有标签 |
| 最近分类推荐 | 按收支方向分别统计高频叶子标签 |

### 核心：预算与资金（已交付）

| 能力 | 现状 |
| --- | --- |
| 月度预算 | DataStore；进度与节奏预警 |
| 周预算余量 | 周起点冻结额度 − 本周∩本月支出（下限 0）；首页「本周还可花」 |
| 持有资金 | 期初总和 + 累计净结余；按账户分组 + 总计 |
| 账户 | 预置微信/支付宝/银行卡；期初余额；增删改名 |
| 转账 | 账户间划转，不计收支/预算/报告 |

### 核心：分类体系（已交付，相对初版有演进）

- 根类：学习 / 社交 / 生活 / 娱乐 + 独立「收入」根（生活费/还款/AA/理财/兼职经营/其他收入）
- **仅叶子可选**，父类只作分组（用户明确「不喜欢笼统标签」）
- 子标签增删改名、拖拽排序；删除前影响面分析
- 整理：未分类批量 LLM 建议，逐条确认后应用
- 整合：重复叶子标签合并（LLM 建议 + 用户确认）
- 生活方式启发式（1.2.0）：囤货三餐 / 外出就餐 / 兼职经营等本地规则

### 核心：报告与复盘（产品主轴：生活费可花额度）

| 能力 | 现状 |
| --- | --- |
| 周报 / 月报 | 打开应用补生成；默认看**本周**；**年报 UI 已停用** |
| 额度 Hero | 复用今日 `MonthlyBudgetSnapshot`（本周还可花 / 本月剩余 / 日均可花） |
| 结构化 | 收支/净结余/日均/Top 分类饼图/分类下钻 |
| 时间纵深 | 近 6 期支出柱、环比、分类增减 |
| 本地叙事 + 建议 | 故事段（可缀额度）+ 周报「下周目标」0–1 / 月报行动建议 0–2 |
| AI 深读 | **按需按钮**，配置 API 后可用；失败不影响报告 |
| 展示形态 | **独立全屏详情页**；列表仅摘要行 |
| 周日提醒 | 周日 **10:00** 轻通知「本周复盘 · 本周还可花」；系统设置可关 |

### 支撑（已交付）

- 收支管理：标签多选 + 时间快捷 + 备注搜索；删除/编辑
- 备份与恢复：SAF JSON，不含 API Key
- 订阅开支管理：扣费推算、到期提醒、一键记账（初版未规划，已落地）
- 视觉：樱粉奶油 M3 主题、Splash、侧栏入口、编辑全屏化

### 明确不做（scope 红线，保持）

- 多成员 / 共享记账
- 商家 / 项目管理
- 人情礼簿 / 物品收纳
- 多币种 / 汇率
- 发票 / 财务云盘
- Web 端 / 小程序

### 学生专属（初版设想 vs 现状）

| 初版设想 | 现状 | 取舍 |
| --- | --- | --- |
| 防冲动消费（超阈值确认、娱乐周限警示） | 未做 | 与「不说教」有张力，待重新设计 |
| 应用锁 / 指纹 / DB 加密 | 未做 | 个人手机单用户，优先级低 |
| 震动反馈 ≤30ms | 未做 | 可作体验打磨 |
| 文案不说教 | 规则洞察已有体现 | 继续作为文案规范 |

## 二、报告产品力（已立项：生活费额度）

> 规格：`docs/compose/spec/report-allowance-review.md`。痛点「只有数字更醒目」→ 以生活费可花额度为主轴。

### 2.1 身份定位（已选）

- **已选：生活费可花额度**（本周还可花 / 本月剩余 / 日均可花）
- 未选（后续可选）：学业四维平衡、自律打卡、合一驾驶舱

### 2.2 日常习惯

- **已做**：周日复盘仪式（默认本周；结构「额度 → 故事 → 下周目标」；周日 10:00 通知）
- 未做：记后即时「今日已花 / 本周剩余」；发钱日切周期

### 2.3 展示形态（已确认）

- 报告详情为独立全屏页；列表摘要含还可花；返回保持列表选中态

---

## 三、MVP 纪律与验证指标

- 记账核心与预算资金是日常使用率主干，优先打磨而非堆功能
- 报告功能以「学生会不会每周打开」为准，不为完整而完整
- 若日常使用率 < 80%，优化交互而非加新功能

## 附录 B · 与初版的主要出入

1. **账户 / 期初余额 / 转账**：初版口径「不引入账户」，后为持有资金与转账需求扩展
2. **年报**：数据模型保留，UI 与补生成已停用
3. **报告 AI**：自动 LLM 分析 → 移除 → 仅保留按需深读
4. **周日通知**：曾实现 → 精简时移除 → 额度规格克制恢复（周日 10:00）
5. **订阅管理**：初版未规划，已交付
6. **父类不可选 / 收入独立根 / 整理 / 整合**：标签体系持续演进
7. **隐私（应用锁/加密）**：未实现

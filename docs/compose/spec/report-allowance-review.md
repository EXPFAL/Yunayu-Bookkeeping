# 报告产品力：生活费额度主轴 + 周日复盘 + 独立详情页

## Report

## [S1] Problem

1.2.0 视觉重塑后用户反馈「只有数字更醒目，没有功能性提升」。报告仍是数据快照，没有回答学生第一问：**生活费还够不够、每天还能花多少、要不要收着点**。
`MonthlyBudgetEngine` 已算出「本周还可花 / 本月剩余 / 剩余天数」并在首页 BudgetCard 展示，但报告详情不承载该主轴，复盘价值弱。

另：报告详情在列表下方展开，需手动下滑；应改为**独立全屏页**。

日常节奏缺失：周报未成为「周日复盘」习惯（周日通知已移除），默认周期与入口未绑定学生周节奏。

## [S2] Design

### 2.1 产品主轴：生活费可花额度

报告**先回答钱，再讲故事**。详情页首屏（Hero）以额度为主，叙事与图表降为解释层。

**Hero（生活费驾驶位）** — 复用今日 `MonthlyBudgetSnapshot`（与首页同源），不改预算算法；**不按历史期键复原**。

| 字段 | 展示 | 说明 |
| ---| ---| ---|
| `weeklyRemainingCents` | 主数字「本周还可花」（周报） | 学生周节奏的行动口径 |
| `remainingCents` | 主数字「本月还可花」（月报） | 月视角 |
| `remainingCents` / `remainingDays` | 副行 | 月视角 |
| `weeklyQuotaCents` / `spentThisWeekCents` | 本周额度进度 | 超额用语义色 |
| 日均可花 | `remainingCents / max(remainingDays,1)` | 预算推导，非新引擎 |
| 状态句 | 规则短句 | 无预算引导；本周超额度→偏快；否则节奏尚可 |

未设月预算：Hero 显示引导态 + 去设置，**不阻塞**下方报告内容。

### 2.2 周日复盘仪式

- **默认周期 = 本周**（打开报告页默认 `WEEKLY`）。
- **列表页摘要**：仅**当前周/当前月**行在有预算时缀「本周/本月还可花 · 净结余」；历史行只显示净结余（避免每条卡片重复同一今日额度）。
- **周日轻提醒**：WorkManager 周日 10:00；文案含「本周还可花」；点击进本周详情。
- **详情页结构**：额度 → 本期故事（可缀额度前缀）→ 下周目标/建议 → 趋势/环比 → 分类 → 细节。
- 周报建议区标题「下周目标」，**只展示首条**；月报「行动建议」最多 2 条。

### 2.3 独立详情页

- `FullScreen.REPORT_DETAIL`；列表点行压栈；返回出栈回列表（保留选中态）。
- 列表不再内嵌展开。

### 2.4 叙事衔接

- 额度前缀在**详情 UI 展示层**拼接，不强制 regenerate 已落库 STORY。
- 不推翻既有评分。

### 2.5 不做

- 不改 `MonthlyBudgetEngine`、不新 schema、不自动 AI、不做四维/打卡/应用锁。

### 2.6 测试边界

- domain：日均可花 / 状态句纯函数
- ui：默认 WEEKLY、进详情出栈、无预算引导、Hero 映射
- Worker：文案含「本周还可花」（假件/单测可测调度常量）

## [S3] Out of Scope

- 学业四维、打卡、应用锁、年报 UI、预算算法变更、多语言、Widget
